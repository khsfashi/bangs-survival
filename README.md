# 앞머리 생존예보

한국 사용자가 외출 전에 **“오늘 앞머리를 세팅할 가치가 있는가?”**를 빠르게 판단하도록 돕는 모바일 우선 오픈소스 웹앱입니다.

## 현재 기능

- 브라우저 현재 위치를 예보 기준점 후보로 사용
- PC geolocation이 실제 위치와 크게 어긋날 수 있음을 UI에서 경고
- 카카오맵 drag/click과 동네·주소 검색으로 위치를 직접 보정
- 사용자가 지도에서 확정한 최근 위치를 현재 브라우저에 저장하고 다음 방문에 재사용
- 새 브라우저 위치와 최근 확인 위치가 10km 이상 차이나면 자동 확정하지 않고 선택 요청
- 카카오 좌표→행정동 변환과 WGS84→기상청 DFS 격자 변환
- `KMA_API_KEY`가 있으면 기상청 동네예보를 우선 사용하고 장애 시 Open-Meteo를 명시적인 fallback으로 사용
- 습도 / 이슬점 / 강수확률 / 풍속 기반 deterministic 생존점수
- 현재 날씨뿐 아니라 앞으로 12시간의 비·습도·바람 변화와 더 좋은 시간대를 반영한 행동 조언
- `유지됨 / 조금 무너짐 / 망함` 피드백을 하루 1개씩 localStorage에 저장
- 3일 이상 피드백부터 제한된 개인 calibration을 점수와 행동 조언에 반영
- 점수에 따라 표정과 앞머리 상태가 달라지는 **고정 여성 SVG 마스코트**
- 헤어롤을 직접 굴려 하루 한 번 뽑는 **12종 앞머리 요정**과 로컬 도감
- 날씨와 어울리는 요정의 확률을 약간 높이되 실제 결과는 랜덤으로 결정
- 연구 논문을 근거로 한 고습도 고정제·열기구·마찰 관련 보조 조언
- 예보를 볼 때마다 123종 중 하나를 무작위로 보여주는 `오늘의 한마디`
- 로그인과 서버 DB 없음

## 앞머리 행동 조언

조언은 고정 문구를 무작위로 선택하지 않습니다. 다음 신호를 deterministic하게 평가해 우선순위가 높은 최대 3개를 표시합니다.

- 현재 강수확률, 습도/이슬점, 풍속
- 앞으로 12시간의 최대 강수확률과 최대 풍속
- 몇 시간 안에 습도나 이슬점이 유의하게 상승하는지 여부
- 현재보다 생존점수가 크게 좋아지는 시간대가 있는지 여부
- 3일 이상 누적된 실제 결과에서 예보보다 쉽게/잘 버티는 개인 경향이 있는지 여부

현재 조언 규칙과 임계값은 제품 가설이며 실제 사용자 결과로 검증해야 합니다.

추가로 `연구 기반 보조 팁`은 사람 모발의 습도 의존성, 고습도에서의 styling polymer 성능, 열기구 손상, 마찰과 conditioner 효과에 관한 논문을 연결합니다. 이 근거는 직접적인 `앞머리 임상시험`이 아니므로 앱에서는 과장하지 않고 보수적인 행동 조언으로만 번역합니다.

## 캐릭터와 앞머리 요정 뽑기

메인 마스코트는 랜덤 avatar generator를 사용하지 않습니다. 앞머리 상태 자체가 제품 정보이므로 하나의 고정 캐릭터가 `great / okay / worried / doomed` 상태에 따라 표정과 앞머리 모양을 바꾸도록 로컬 SVG로 구성합니다.

`오늘의 앞머리 요정`은 사용자가 **핑크 헤어롤을 직접 굴려 뽑는 하루 1회 랜덤 수집 요소**입니다.

- 12종 요정과 `일반 / 희귀 / 반짝` 3단계 희귀도
- 실제 날씨 종류와 affinity가 맞는 요정의 weight를 1.8배로 높이지만 결과 자체는 랜덤
- 브라우저에서는 `crypto.getRandomValues`를 우선 사용하고 지원하지 않으면 `Math.random`으로 fallback
- 같은 날짜에는 첫 결과를 저장하여 재뽑기할 수 없음
- 최대 120일의 뽑기 기록만 현재 브라우저 localStorage에 저장
- 도감에서는 만나 본 종류만 정상 색상과 이름으로 표시
- 재화, 유료 뽑기, 광고 보상 reroll, punitive streak 없음
- 놓친 날이 있어도 불이익 없음
- 헤어롤과 요정은 모두 작은 로컬 SVG라서 캐릭터 때문에 외부 네트워크 요청을 하지 않음

헤어롤 시각 형태는 SVG Repo의 CC0 `Hair Rollers`를 prior art로 확인했습니다. 원본 전체를 런타임 자산으로 가져오기보다 현재 UI에 필요한 실린더·롤 홈·손잡이 형태만 작은 로컬 SVG로 다시 구성했습니다. DiceBear, React Kawaii, Microsoft Fluent Emoji, Crittericons, OpenMoji 등을 비교한 결과도 [`PRIOR_ART.md`](./PRIOR_ART.md)에 기록합니다.

## 오늘의 한마디

예보 결과를 볼 때 `encouragement.js`의 123개 고유 문구 중 하나를 무작위로 선택합니다. 점수와 별개로 과도한 자기비하나 외모 압박을 강화하지 않고, 준비를 마친 뒤 기분을 가볍게 환기하는 짧은 문구만 포함합니다.

## 환경변수

Vercel 프로젝트에 아래 값을 설정합니다.

```text
KAKAO_JAVASCRIPT_KEY=<Kakao Maps Web JavaScript key>
KMA_API_KEY=<KMA APIHub auth key>
```

### Kakao Maps 키

`KAKAO_JAVASCRIPT_KEY`는 지도 Web SDK를 브라우저에서 로드하기 위한 클라이언트 공개 키입니다. 값 자체를 비밀키처럼 숨길 수 없으므로 Kakao Developers에서 서비스할 Vercel/커스텀 도메인을 허용 도메인으로 제한해야 합니다. REST API 키, Admin 키 등 다른 인증정보를 이 환경변수에 넣으면 안 됩니다.

### KMA API 키

`KMA_API_KEY`는 `/api/weather` Vercel Function에서만 사용합니다. 브라우저 응답이나 저장소에는 노출하지 않습니다.

## 위치와 개인정보

- 브라우저 geolocation은 현재 예보 후보를 계산하는 용도로 사용하며 서버 DB에 저장하지 않습니다.
- 브라우저가 제공하는 `coords.accuracy`는 실제 오차를 항상 보장하지 않습니다. 특히 PC/Wi-Fi 환경에서는 수십 km 이상 틀릴 수 있어 지도 확인 경로를 제공합니다.
- 사용자가 지도/검색 후 직접 확정한 최근 위치의 좌표와 행정동은 다음 사용을 위해 현재 브라우저 localStorage에만 저장합니다.
- 저장된 최근 위치는 새 브라우저 위치가 크게 튀었는지 판단하는 로컬 기준점으로도 사용합니다.
- 민감도 설정, 결과 피드백, 하루 1회 요정 뽑기 기록 역시 현재 브라우저 localStorage에만 저장합니다. 응원 문구는 별도 기록하지 않습니다.
- 화면에는 사용자가 선택한 행정동과 실제 기상청 격자 `(nx, ny)`를 함께 보여줍니다.
- 마스코트와 요정은 로컬 SVG이므로 캐릭터 렌더링을 위해 위치나 식별정보가 외부 자산 서버로 전송되지 않습니다.

## 예보 데이터 정책

한국에서는 기상청 동네예보를 우선 데이터 공급원으로 사용합니다. 기상청 경로를 사용할 수 없는 경우에만 Open-Meteo를 fallback으로 유지합니다. 어떤 공급원을 사용했는지는 UI에 표시합니다.

현재 생존점수의 변수 선택에는 모발과 습도의 관계에 관한 선행 연구 근거가 있지만, 가중치와 임계값은 아직 제품 가설입니다. 실제 사용자 데이터로 검증하기 전에는 예측 정확도를 주장하지 않습니다.

## 테스트

외부 테스트 프레임워크 없이 Node 내장 테스트 러너를 사용합니다.

```bash
npm test
```

현재 테스트는 다음을 포함합니다.

- 기상 위험도 범위
- 서울·부산·제주·강남의 KMA 격자 변환 검증
- 이슬점 계산과 기상청 발표시각 선택
- KMA 응답 정규화
- 현재 날씨와 미래 추세에 반응하는 앞머리 행동 조언
- 충분한 실제 결과가 쌓인 이후에만 노출되는 개인화 조언
- 점수별 판정과 마스코트 상태
- 하루 1회 피드백 upsert와 개인 보정 상한
- 12종 요정 catalog, 희귀도, 날씨 affinity 가중 랜덤 선택과 하루 1회 upsert
- 요정/헤어롤 로컬 SVG가 원격 이미지 URL을 포함하지 않는지 확인
- 연구 기반 보조 팁의 조건별 선택과 HTTPS 논문 출처 검증
- 123개 응원 문구의 고유성과 랜덤 picker 범위 검증
- 구형 localStorage 데이터 호환
- 두 좌표 사이 거리 계산과 큰 위치 점프 판정
- 최근 확인 위치 정규화/유효성 검증

## 개발 진행 방식

[`AGENTS.md`](./AGENTS.md)에 프로젝트 인수인계와 다음 작업 결정 규칙을 기록합니다.

`@GitHub bangs-survival 다음 작업 진행해줘`

처럼 요청하면 open PR → issue → prior-art → 테스트 상태를 확인하고 다음 작업을 이어서 진행합니다.

새 기능은 `Need -> Research -> OSS/Commercial -> Gap -> Feasibility -> Build/Don't Build` 순서로 검토하여 이미 잘 해결된 문제를 불필요하게 다시 구현하지 않습니다.
